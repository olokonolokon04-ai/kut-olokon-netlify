КУТ — УСТАНОВКА НА NETLIFY

1. Распакуйте архив kut_netlify_project.zip.
2. Создайте в GitHub новый PRIVATE repository и загрузите в него содержимое папки проекта. Не загружайте .env, пароли, реальные паспорта или сканы.
3. В Netlify откройте unrivaled-pixie-aec02c → Project configuration → Build & deploy → Continuous deployment и подключите этот GitHub repository.
4. В Netlify откройте Data & Storage → Database, создайте PostgreSQL Database и проверьте расход кредитов. Включите Sleep on inactivity (минимум 5 минут).
5. Откройте локально GENERATE_SECRETS.html и сгенерируйте три ключа. Добавьте их в Project configuration → Environment variables: KUT_SETUP_TOKEN, KUT_SESSION_SECRET, KUT_DATA_ENCRYPTION_KEY. Не присылайте ключи в чат и не коммитьте в GitHub.
6. Запустите production deploy. В Deploy log проверьте, что SQL-миграция применена без ошибок.
7. Откройте https://unrivaled-pixie-aec02c.netlify.app/setup и создайте администратора. Затем удалите KUT_SETUP_TOKEN из Environment variables и сделайте новый deploy. Два других ключа не меняйте.
8. Войдите на /login, создайте два отдельных аккаунта операторов. Проверьте процесс на вымышленных данных с двух компьютеров: ПК №1 оформляет, ПК №2 нажимает «Обновить список» и подтверждает.
9. После проверки нажмите Make public, чтобы сотрудники могли открыть production-сайт. На странице сайта будет вход в КУТ; API должен отдавать данные и файлы только после проверки логина и прав.

ВАЖНО:
• В присланном скриншоте отображалось 74 кредита. Netlify Database расходует кредиты на вычисления и трафик — проверьте Billing/Usage прежде, чем включать её для постоянной работы.
• Общий размер файлов одной отправки ограничен 3,2 МБ.
• Не используйте настоящие паспорта до успешного тестирования входа, HTTPS, подтверждения вторым сотрудником и резервного копирования.
