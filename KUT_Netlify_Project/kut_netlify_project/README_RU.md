# КУТ — серверное приложение пропусков ЖК «Олокон» для Netlify

Это полный исходный проект для Netlify, а не одиночный HTML-файл. В нём сохранён текущий макет пропуска КУТ и добавлены серверный API, общая PostgreSQL-база, закрытое хранилище документов и отдельное подтверждение вторым сотрудником.

## Что делает приложение

- Сохраняет текущий внешний вид пропуска, предпросмотр и печать по 10 карточек на листе A4.
- Даёт отдельные учётные записи администратору и каждому оператору.
- Позволяет вручную вводить фамилию, имя, отчество, отдел и должность.
- Прикрепляет фото сотрудника и до пяти паспортных сканов (JPG, PNG, WEBP или PDF).
- Сохраняет дополнительные паспортные поля в зашифрованном виде в PostgreSQL, а файлы документов — в Netlify Blobs с шифрованием приложения AES-256-GCM.
- Не использует OCR: ФИО вводится вручную, паспорт прикладывается как документ.
- Ставит новую запись в состояние «Ожидает подтверждения».
- Запрещает автору записи подтверждать её самостоятельно. Подтвердить или вернуть запись может другой сотрудник под другим логином.
- Возвращает запись на исправление с обязательным комментарием; автор может исправить и отправить её повторно.
- Показывает в печати только подтверждённые записи.
- Выдаёт фото и паспорта через авторизованный API. Прямых публичных ссылок на паспортные файлы нет.
- Позволяет администратору создавать пользователей, отключать им доступ и удалять записи.

**Разделение прав:** после подтверждения фото сотрудников доступно всем вошедшим операторам для общего предпросмотра и печати. Паспортные сканы и дополнительные паспортные поля доступны администратору, автору записи и назначенному проверяющему. У каждого сотрудника должен быть свой логин.

## Важно о Netlify и расходе кредитов

Netlify Database — управляемый PostgreSQL, но он доступен на кредитных тарифах и расходует кредиты на вычисления и исходящий трафик. В документации указан расход 10 кредитов за один compute unit; при минимальной вычислительной мощности один compute unit соответствует примерно одному часу работы базы. Фактический расход зависит от времени активности и настроек сна.

В присланном вами скриншоте отображалось 74 оставшихся кредита. По одному скриншоту я не могу подтвердить, относятся ли они к общему балансу или только к AI Agent, поэтому перед включением базы проверьте раздел Billing/Usage. 74 кредита могут покрыть лишь короткий тест, если это общий баланс.

Чтобы не держать базу постоянно активной, приложение **не опрашивает её автоматически**. Второй сотрудник нажимает «Обновить список», когда нужно увидеть новые записи. В параметрах базы оставьте включённым Sleep on inactivity (минимум 5 минут) и не увеличивайте Auto-scale без необходимости. Если лимитов вашего плана недостаточно, не включайте базу и не загружайте реальные паспорта — тогда нужно будет выбрать отдельную внешнюю PostgreSQL или подходящий план.

## Состав комплекта

- `public/index.html` — интерфейс КУТ, форма сотрудника, очередь подтверждения, список пользователей, предпросмотр и печать.

- `public/setup.html` — однократное создание первого администратора.
- `netlify/functions/api.mjs` — API входа, сотрудников, файлов, подтверждения и пользователей.
- `netlify/database/migrations/202611060001_initial_schema.sql` — создание таблиц PostgreSQL.
- `GENERATE_SECRETS.html` — локальный генератор трёх секретов.
- `netlify.toml`, `package.json`, `.nvmrc` — конфигурация проекта.

## Установка в ваш Netlify-проект

### 1. Создать приватный GitHub-репозиторий

1. Распакуйте архив `kut_netlify_project.zip`.
2. В GitHub создайте новый **Private repository**, например `kut-olokon-netlify`.
3. Загрузите **содержимое** папки проекта в корень репозитория: `netlify.toml`, `package.json`, `public/`, `netlify/`, `scripts/`, `.nvmrc`, `.gitignore`, `README_RU.md` и `GENERATE_SECRETS.html`.
4. Не загружайте `.env`, реальные паспорта, сканы, пароли и секретные ключи.

### 2. Подключить репозиторий к Netlify

1. Откройте проект `unrivaled-pixie-aec02c` в Netlify.
2. Перейдите в **Project configuration → Build & deploy → Continuous deployment** и выберите **Link repository / GitHub**.
3. Выберите приватный репозиторий `kut-olokon-netlify`.
4. Убедитесь, что значения сборки такие:
   - Build command: `npm run build`
   - Publish directory: `public`
   - Functions directory: `netlify/functions`
5. Сохраните настройки и запустите production deploy.

Если текущий проект Netlify Drop не предлагает подключить GitHub, создайте новый Netlify project из этого репозитория. Старый проект не удаляйте, пока новая версия не прошла проверку.

### 3. Создать PostgreSQL Database

1. Откройте в Netlify **Data & Storage → Database**.
2. Создайте базу, если она не была создана автоматически при deploy.
3. Во время production deploy Netlify должен применить SQL-миграцию из `netlify/database/migrations/`. Проверьте Deploy log — миграция должна пройти успешно.
4. В настройках базы оставьте включённым **Sleep on inactivity** с минимальным доступным временем. На экране расхода проверьте Compute и Bandwidth.

### 4. Добавить секретные переменные

1. На своём компьютере откройте файл `GENERATE_SECRETS.html` в браузере.
2. Нажмите «Сгенерировать новые ключи».
3. В Netlify откройте **Project configuration → Environment variables** и создайте три переменные:
   - `KUT_SETUP_TOKEN`
   - `KUT_SESSION_SECRET`
   - `KUT_DATA_ENCRYPTION_KEY`
4. Скопируйте значения из локального генератора. Не отправляйте их в чат и не сохраняйте в GitHub.
5. Запустите ещё один production deploy, чтобы функции получили переменные.

**Не меняйте `KUT_DATA_ENCRYPTION_KEY` после начала эксплуатации.** Если потерять этот ключ, сохранённые паспортные сканы и зашифрованные поля нельзя будет расшифровать. Храните резервную копию ключа в защищённом месте, отдельно от GitHub.

### 5. Создать администратора

1. Откройте `https://unrivaled-pixie-aec02c.netlify.app/setup`.
2. Введите `KUT_SETUP_TOKEN` и задайте логин администратора и пароль длиной не менее 14 символов.
3. После сообщения об успешном создании удалите `KUT_SETUP_TOKEN` из Environment variables.
4. Запустите новый production deploy. Два остальных ключа должны остаться без изменений.

### 6. Создать операторов и проверить процесс

1. Войдите через `https://unrivaled-pixie-aec02c.netlify.app/login` под администратором.
2. Откройте «Пользователи» и создайте два отдельных аккаунта операторов.
3. На ПК №1 зайдите под оператором №1, введите вымышленные данные, прикрепите тестовый паспорт и фото. Запись должна получить статус «Ожидает подтверждения» и не попасть в печать.
4. На ПК №2 войдите под оператором №2, нажмите «Обновить список», откройте документы и подтвердите запись.
5. Вернитесь на ПК №1, нажмите «Обновить список». Статус должен стать «Подтверждён», а пропуск — появиться в печати.
6. Отдельно проверьте возврат с комментарием и повторную отправку записи её автором.

### 7. Открыть сайт сотрудникам

Сейчас ваш проект в Netlify помечен как **Private**. В этом режиме сайт закрыт для людей, которых нет в вашей команде Netlify. На Free/Personal-планах приватный проект обычно доступен только владельцу команды; для доступа сотрудникам к приватному проекту Netlify может потребоваться платный план с приглашением участников.

Когда вход КУТ, секреты и права API уже настроены и проверены, нажмите **Make public** для production-проекта, чтобы работники могли открыть сайт по адресу Netlify. Это откроет веб-страницу проекта всем, у кого есть ссылка, но внутренние данные приложения должны оставаться закрытыми: сотрудники увидят форму входа, а API выдаёт записи и файлы только после проверки отдельного логина и прав доступа. Не делайте проект публичным до завершения первоначальной настройки.

## Ограничения загрузки

Общий размер выбранных фото и паспортных файлов в одной отправке — до 3,2 МБ; один файл — до 3 МБ. Это ниже эффективного лимита буферизованных Netlify Functions для бинарных запросов с учётом Base64-накладных расходов. Если скан больше, уменьшите разрешение/качество или сохраните изображение в JPG.
